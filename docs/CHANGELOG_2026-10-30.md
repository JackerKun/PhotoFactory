# PhotoFactory 2026-10-30 更新记录

## 本地语义标签升级

- 开发前创建恢复分支 `backup/pre-semantic-tags-20261030`，不改动用户照片目录和现有 `.pf` 数据。
- 新增量化 CLIP ViT-B/32 本地语义模型，在 Places365 场景之外识别人像、合影、婚礼、旅行、运动、动物、食物、交通、自然、天气、建筑和常见物品等多类内容。
- 每张照片最多保存 8 个语义标签、同类最多 2 个，并使用可信度门槛控制噪声；模型不可用时自动降级到原有场景标签，不阻塞整个 AI 队列。
- 标签页新增“智能分类”视图，按类别展示标签来源、照片数和平均可信度，支持搜索与“只显示可靠结果”；原来的新增、改名、颜色和删除操作保留在“可编辑标签”。
- 智能分类只聚合有上限的固定词表，不随照片数量线性增加界面节点，适用于十万级照片库。
- 内容任务模型版本升级为 `places365-v1+clip-vitb32-int8-v1`；已有照片只会重新进入可断点续跑的内容分析队列，不会重跑人脸或改动已命名人物。
- macOS、Windows 和 PyInstaller 构建流程已加入语义分类模块、Tokenizer 运行库以及三个模型资源，发布包可离线运行。

## 已命名人物合并修复

- 修复两个已命名或已确认人物合并时，源人物元数据外键导致 `FOREIGN KEY constraint failed` 的问题。
- 单个合并和批量合并现在都会在同一事务内依次移动人脸、移除冗余源元数据、删除源分组并刷新目标计数；目标人物的姓名与元数据保持不变。
- 增加两个同名人物且均带人物元数据时的合并回归测试。

## 人物缩略图增加环境视野

- 人物卡片不再直接使用紧贴五官的人脸框，改为约 1.8 倍的正方形头肩视野。
- 裁剪中心略向下偏移，在保留完整头部的同时展示更多肩部和周边内容，便于辨认人物。
- 缩略图缓存升级为新版本，旧的紧裁剪缓存不会继续显示，无需手动清理 `.pf`。
- 人物页改为服务端按标签分页，每次最多加载 96 个分组；缩略图仍按可视区域懒加载，并保留 200 项内存缓存上限。
- 新增人物数量排序索引，避免十万级照片库打开人物页时一次性查询和渲染全部分组。

本次更新集中解决大型照片库中“人物分组过碎、无关人物难清理、专业整理能力不足”和 HEIC 预览偶发失败等问题。开发前创建了 Git 恢复点，所有改动在独立分支完成。

## HEIC/HEIF 稳定性

问题根因是地图小图、Photo Details 大图和后台缩略图任务可能同时处理同一 HEIC：旧实现共用一个转码 JPEG，并直接写最终 WebP，导致某个请求删除另一任务的临时文件，或 WebView 读到尚未写完的缩略图。

修复后：

- 每次 HEIC/RAW 转码使用唯一临时 JPEG；
- WebP 先写入唯一临时文件，完整编码后再原子发布；
- 并发任务最终返回同一个完整、可解码的缓存文件；
- Photo Details 对生成请求重试 3 次，对 WebView 解码失败额外重试 2 次；
- 新增 8 线程同时生成同一缩略图的回归测试。

- 相似指纹聚合由全库两两比较改为六段多索引分桶候选，再执行相同的精确汉明距离判断，保持匹配规则同时显著降低大图库计算量。

## 十万级人脸管线

- 新增 `ai_photo_tasks` 持久化任务表，以照片、阶段、模型版本和源文件指纹记录 pending/running/done/failed、尝试次数、租约和错误。
- 人脸结果替换、完成标记和任务完成状态使用单照片事务提交；异常退出后重启会回收旧租约，从未完成照片继续，并避免产生重复的自动人脸。
- 单照片失败最多自动重试 3 次，失败任务与正常队列隔离，可从侧栏统一重试。
- 新增持久化管线状态、速度和 ETA；侧栏支持暂停、停止、继续和重试失败，暂停与停止不会丢失已完成结果。
- AI Worker 根据机器核心数在 2–6 个推理线程间自适应，并使用两个有界人脸工作线程重叠解码与推理。
- JPEG 人脸输入使用解码期降采样；ArcFace 在模型支持动态批量时合并同一照片中的多张人脸输入。
- 人物聚类每处理约 500 张照片增量发布一次，每批最多接收 1000 张待分组人脸。
- 日常增量聚类只读取本批新脸和每个既有人物最多 3 个高质量代表特征，不再重载全部历史 `.npy`；首次聚类也被拆分为有界批次。
- 新增模型版本变化重排队、失败重试、租约恢复和增量候选范围回归测试。

## 数据与安全语义

- 回收站、忽略人物、隐私标记、相册和故事都不会删除或移动原始照片。
- XMP 导出会在原图旁新增文件，是本次扩展中需要目标目录写权限的操作。
- 非破坏编辑只保存参数，不改写原图像素。
- 删除 `.pf` 会删除项目索引及所有整理结果，但不会删除原始照片。
- 旧数据库自动迁移；正常升级不需要删除 `.pf`。
